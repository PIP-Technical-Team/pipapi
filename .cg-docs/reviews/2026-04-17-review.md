### P0 — BLOCKING (immediate remediation required)

- **[P0.1]** [cg-data-quality / cg-reproducibility] `R/duckdb_func.R:414` — Authentication bypass when both env vars are unset.
  **Why**: `pass` defaults to `Sys.getenv('PIP_CACHE_LOCAL_KEY')`, which returns `""` when not set. `Sys.getenv('PIP_CACHE_SERVER_KEY')` also returns `""`. `"" != ""` is `FALSE`, so the guard never fires — two unset vars silently permit cache deletion. Same defect exists in the sibling `reset_cache()`.
  **Fix**:
  ```r
  local_key  <- Sys.getenv("PIP_CACHE_LOCAL_KEY",  unset = NA_character_)
  server_key <- Sys.getenv("PIP_CACHE_SERVER_KEY", unset = NA_character_)
  if (is.na(local_key) || !nzchar(local_key) || is.na(server_key) || !nzchar(server_key)) {
    rlang::abort("Cache key env var(s) not set (PIP_CACHE_LOCAL_KEY / PIP_CACHE_SERVER_KEY).")
  }
  if (pass != server_key) {
    rlang::abort("Cache key mismatch: supplied key does not match server key.")
  }
  ```

- **[P0.2]** [cg-data-quality / cg-architecture] `inst/plumber/v1/endpoints.R` — `/api/v1/cache-delete` endpoint is unauthenticated.
  **Why**: The `cache-delete` endpoint calls `unlink(cd$info()$dir, recursive = TRUE)` with no password/key check. Any HTTP client that can reach the API can wipe the entire cache directory with a plain GET. The new `delete_cache()` function has key validation, but it is not used here.
  **Fix**: Either route through `pipapi:::delete_cache(pass, lkup = lkup)` (consistent with `reset_cache` pattern), or add an explicit key check matching the pattern used in `duckdb-reset`.

### P1 — CRITICAL (must fix before merge)

- **[P1.1]** [cg-version-control / cg-code-quality] `inst/TMP/TMP_duckdb_cache.R:31` — Hardcoded credential values committed to a file inside `inst/`.
  **Why**: `Sys.setenv(PIP_CACHE_LOCAL_KEY = 'abc', PIP_CACHE_SERVER_KEY = 'abc')` is committed. `inst/` contents ship in the installed R package tarball, so this placeholder pattern is readable by end users and normalises committing env-var assignments.
  **Fix**: Remove the `Sys.setenv()` line and replace with a comment: `# Set PIP_CACHE_LOCAL_KEY and PIP_CACHE_SERVER_KEY in .Renviron`. Add `inst/TMP/` to `.gitignore` and `.Rbuildignore`.

- **[P1.2]** [cg-architecture] `inst/plumber/v1/endpoints.R:451` — `delete_cache()` is dead code from the API's perspective.
  **Why**: The new function is defined, tested, but never called from the router. `cache-delete` still uses the unauthenticated `unlink()` path (see P0.2). If introduced to replace `unlink()`, the endpoint was not updated.
  **Fix**: Either wire `cache-delete` to call `delete_cache()`, or add a clear comment explaining why the function is intentionally not used by the router.

- **[P1.3]** [cg-testing] `tests/testthat/test-reset_cache.R` — Auth failure case is untested.
  **Why**: The key-mismatch guard is the only security control in `delete_cache()`. No test verifies it aborts when keys differ or when env vars are unset. A regression could silently remove the guard without any test failing.
  **Fix**:
  ```r
  test_that("delete_cache aborts when pass does not match server key", {
    withr::local_envvar(PIP_CACHE_SERVER_KEY = "server-key")
    expect_error(delete_cache(pass = "wrong-key", lkup = list(data_root = withr::local_tempdir())),
                 class = "rlang_error")
  })
  test_that("delete_cache aborts when PIP_CACHE_SERVER_KEY is unset", {
    withr::local_envvar(PIP_CACHE_SERVER_KEY = "")
    expect_error(delete_cache(pass = "", lkup = list(data_root = withr::local_tempdir())),
                 class = "rlang_error")
  })
  ```

- **[P1.4]** [cg-data-quality] `R/duckdb_func.R:420` — No validation of `lkup$data_root` before use.
  **Why**: If `lkup` is missing or `lkup$data_root` is `NULL`/empty, `fs::path(NULL, ...)` throws a cryptic error. There is no early guard as found in other functions in the file.
  **Fix**:
  ```r
  if (is.null(lkup$data_root) || !nzchar(lkup$data_root)) {
    rlang::abort("`lkup$data_root` is NULL or empty — cannot locate cache file.")
  }
  ```

- **[P1.5]** [cg-data-quality] `inst/plumber/v1/endpoints.R` — Five live endpoints (`cache-reset`, `cache-get`, `cache-keys`, `cache-info`, `duckdb-reset`) are absent from `openapi.yaml`.
  **Why**: These endpoints are reachable but undocumented in the spec, creating a hidden surface. `duckdb-reset` in particular accepts a `pass` parameter — documenting it allows validation tooling to spot misuse.
  **Fix**: Add all five under a `Cache Management` tag in `openapi.yaml`, with appropriate notes (read-only vs. mutating, `pass` parameter where required).

- **[P1.6]** [cg-documentation] `inst/plumber/v1/openapi.yaml:30` — `license: MIT` misrepresents the World Bank data license.
  **Why**: PIP's poverty data is governed by World Bank Terms of Use, not MIT. Misrepresenting the license could mislead consumers about redistribution rights for the data.
  **Fix**: Change to `name: "Creative Commons Attribution 4.0"` / `url: "https://creativecommons.org/licenses/by/4.0/"` or the explicit World Bank terms URL. Verify with the data team.

- **[P1.7]** [cg-data-quality] `R/duckdb_func.R:421` — No active-connection guard before file deletion.
  **Why**: DuckDB holds exclusive file locks when a connection is open. Deleting the `.duckdb` file with an open connection fails silently on Windows or leaves the WAL orphaned. `reset_cache()` handles this by opening and closing a connection; `delete_cache()` does not.
  **Fix**: Document in roxygen that callers must close all DuckDB connections before calling, or wrap `fs::file_delete` in a `tryCatch` with a clear error message.

- **[P1.8]** [cg-code-quality] `tests/testthat/test-reset_cache.R:225` — Hardcoded absolute Windows path in a committed test.
  **Why**: `real_data_root <- "E:/PIP/pipapi_data/20260430_2017_01_02_INT"` is machine-specific and will silently become stale as vintages rotate. The test comment says "TMP: Delete this test once..." — it should be deleted now.
  **Fix**: Delete the TMP live test, or drive path from an env var:
  ```r
  real_data_root <- Sys.getenv("PIPAPI_TEST_REAL_DATA_ROOT", unset = "")
  skip_if(nchar(real_data_root) == 0 || !dir.exists(real_data_root),
          "Real data directory not available")
  ```
